# Накладные и списания на FastAPI

## Состояние выпуска

Реализован нативный обработчик документов и долговечная очередь отправки. По умолчанию оба выключены. Пока `CHAIKA_DOCUMENTS_NATIVE_ENABLED=false`, сайт продолжает обращаться к прежнему сервису через `CHAIKA_WEB_DOCUMENTS_API_URL`. Наличие кода в Git не означает переключения production.

Модуль `app/documents` не импортирует Django. Он использует существующие таблицы закрытой схемы `chaika_iiko_documents` и отдельную роль `chaika_iiko_app`. Повторного импорта истории, пользователей, прав и Telegram-привязок нет. Аналитическая роль и Supabase Auth не получают новых прав записи.

## Что перенесено

- Списки, фильтры, состав, история и CSV накладных и списаний.
- Создание, изменение, копирование и отмена накладных; создание списаний.
- Согласование и отклонение с проверкой версии документа и прав конкретного склада.
- Управление связью рабочего профиля с аккаунтом dashboard, доступами и Telegram ID.
- Уведомления Telegram, `/start`, `/pending`, ранее выпущенные кнопки с версией документа.
- Ежедневное обновление справочников товаров и складов в 06:00 по Москве. На запросы сайта iiko не вызывается.
- Отправка документов отдельным процессом, восстановление очереди после перезапуска и журнал сверки спорных результатов.

Это перенос модуля документов. Отдельные прежние функции — журнал расходов, гостевой Excel, специальные отчёты и утренняя рассылка с окраской номенклатуры — требуют отдельной сверки использования. Их нельзя считать перенесёнными или останавливать вместе с модулем документов без проверки.

## Как работает очередь

### Уведомления Telegram

Новые уведомления и `/pending` показывают оформленный текст CHAIKA: номер и версию,
склады или причину списания, полный состав, комментарий, автора и дату по Москве.
Текст можно искать и копировать, размер шрифта задаётся приложением Telegram.
Данные документа экранируются перед HTML-форматированием; изображения не отправляются.
Количество сохраняет исходную точность. Единица показывается только при наличии в данных:
текущий справочник документов содержит названия без единиц.

Длинный документ разбивается на страницы без обрезания позиций. Кнопки «Согласовать» и
«Отклонить» прикрепляются только к последней странице; проверка версии и прав прежняя.
Неопределённый результат отправки сообщения, включая частичную отправку страниц, остаётся
`unknown` без автоматической повторной рассылки. Уже отправленные сообщения не изменяются.
Если worker размещён отдельно от API, обновить нужно и его образ: одного деплоя сайта
недостаточно для смены оформления уведомлений.

### Сохранение согласования

Согласование в одной транзакции PostgreSQL проверяет профиль, права склада и версию, сохраняет автора согласования, неизменяемый пакет для iiko, запись операции и задачу очереди. Ответ сайта возвращается после сохранения в БД, без ожидания iiko. Редактирование уже согласованной версии запрещено.

| Состояние | Поведение |
| --- | --- |
| `idle` | Заявка ожидает согласования |
| `queued` | Согласована; сохранена в очереди |
| `sending` | Отправка началась; повтор запрещён |
| `sent` | Получено подтверждение приёма iiko; проведение проверяется в iiko |
| `rejected` | Получен определённый отказ; нужна проверка и новое согласование |
| `unknown` | Документ мог быть принят; автоматического повтора нет |

При недоступности соединения/авторизации до отправки повторы идут через 15, 30, 60, 120, 240, 480 и далее 600 секунд. Задача не теряется при перезапуске приложения. Уникальная операция, блокировка строки и номер версии защищают от двух одновременных согласований на сайте и в Telegram. Старый обработчик не может завершить задачу, захваченную новым процессом.

Если POST уже мог достичь iiko, потеря ответа, неизвестный ответ и завершение процесса переводят отправку в `unknown`. Ответ HTTP 5xx сам по себе не доказывает, что записи нет. Для такой задачи требуется сверить документ в iiko; слепых повторов нет. Это не обещание exactly-once между PostgreSQL и внешней системой.

Пакет сохраняет прежнюю операцию: накладная — `documents/import/outgoingInvoice`, списание — `v2/documents/writeoff`. Накладная не превращается в `internalTransfer`. Момент документа приводится к часовому поясу Крыма перед передачей iiko.

Статус согласования и принятия iiko различается. Очередь не меняет существующие складские права, не делает администратора согласующим всех складов и не открывает аналитику пользователям только документов.

## Конфигурация

Образцы без значений секретов находятся в `.env.example`. Для production:

- `CHAIKA_WEB_DOCUMENTS_ENABLED=true` — разделы документов.
- `CHAIKA_DOCUMENTS_NATIVE_ENABLED=true` — чтение и запись напрямую из FastAPI.
- `CHAIKA_DOCUMENTS_WORKER_ENABLED=true` — фоновые отправки, Telegram и справочники.
- `CHAIKA_DOCUMENTS_DATABASE_URL` — DSN существующей роли `chaika_iiko_app`, доступный из контейнера.
- `CHAIKA_DOCUMENTS_IIKO_URL`, `CHAIKA_DOCUMENTS_IIKO_LOGIN`, `CHAIKA_DOCUMENTS_IIKO_PASSWORD_HASH` — прежнее подключение документов; пароль здесь уже SHA1, в отличие от `CHAIKA_IIKO_PASSWORD` аналитики.
- `CHAIKA_DOCUMENTS_BOT_TOKEN` — токен существующего бота, только после остановки старого polling.
- `CHAIKA_DOCUMENTS_TELEGRAM_LOCAL_ADDRESS` — пусто для автоматического выбора, `::` для IPv6 или `0.0.0.0` для IPv4. Меняет только соединения Telegram; HTTPS проверяется обычным способом. Выбранное семейство адресов должно быть доступно из контейнера.
- `CHAIKA_DOCUMENTS_DASHBOARD_URL=https://dashboard.chaika.team` — ссылки в уведомлениях.

API запускается обычной командой `python -m app.serve`. Он контролирует дочерний процесс `python -m app.documents.worker` и перезапускает его при неожиданном завершении. При нескольких репликах цикл обработчика защищён блокировкой PostgreSQL. Можно запускать worker отдельно, оставив автоматический запуск выключенным в процессе API. Нельзя одновременно запускать прежний Django-бот.

Справочники можно подготовить отдельно, без отправки документов и Telegram:

```sh
python -m app.documents.worker --refresh-catalogs
```

Отсутствие или устаревание справочника блокирует ввод новых товаров. Просмотр исторического состава использует последнюю сохранённую копию.

## Безопасное переключение

1. Сверить активные сервисы старого хоста и все потребители токена Telegram. Сохранить конфигурацию и свежий backup `chaika_iiko_documents`, проверить восстановление в отдельной БД. Не менять старую исходную базу и другие проекты.
2. Применить `migrations/documents/0001_native_runtime.sql` от владельца `chaika_iiko_migrator`. Миграция только добавляет четыре приватные таблицы; не меняет документы, профили и права. Приложение само миграции не запускает.
3. Передать отдельный DSN и интеграционные параметры в защищённые переменные платформы. Пока оставить native/worker выключенными. Проверить чтение и права роли, подготовить справочники.
4. Закрыть старые входы записи и остановить Django backend, Telegram bot, notifications и catalogs. Убедиться, что нет продолжающейся отправки. Все старые `sending`/`unknown` операции сверить до переключения. Старый код не понимает `queued`: совместная работа двух версий запрещена.
5. Включить native и worker в новом backend, дождаться конкретного успешного деплоя. Сверить опубликованный commit, журнал без ошибок и `native_jobs` с `name='heartbeat'`. `/api/health` сам по себе не подтверждает работоспособность очереди.
6. Проверить авторизацию, списки, карточки, существующие складские права и 403 чужого профиля. Первую реальную отправку проверять только на выбранном рабочем документе, затем сверить номер, склад, позиции, количество и дату в iiko. Произвольные тестовые накладные в production не создавать.
7. Публиковать frontend со статусом очереди вместе с включением native backend. Пока старый backend активен, текст про асинхронную отправку пользователям не показывать.
8. Перенаправлять старый домен только после проверки всех нужных старых маршрутов и оставшихся функций. Нельзя просто переносить DNS до этой проверки. Старые кнопки без версии должны требовать `/pending`, а не согласовывать неизвестный состав.

## Наблюдение

Проверки выполняются приватной ролью документов, не публичным Supabase API:

```sql
SELECT state, count(*), min(created_at) AS oldest
FROM chaika_iiko_documents.native_dispatch GROUP BY state;
SELECT name, updated_at FROM chaika_iiko_documents.native_jobs;
SELECT name, updated_at FROM chaika_iiko_documents.native_catalog;
SELECT state, count(*) FROM chaika_iiko_documents.native_bot_updates GROUP BY state;
```

Очередь `ready`/`connecting` длительное время означает проблему связи/авторизации. `unknown` требует сверки. В журналах не выводятся документы, пароли и токены. Не публикуйте содержимое `payload`/`data` и приватный DSN.

## Сверка неизвестной отправки

Остановить отправителей и сопоставить в iiko номер DJ, дату, склад и весь состав. Сохранить доказательство. Команда без `--apply` только показывает локальное состояние:

```sh
python -m app.documents.reconcile waybill 123
python -m app.documents.reconcile waybill 123 --version 2 --result sent \
  --operator 'Имя оператора' --evidence 'Номер и состав сверены с документом iiko …' \
  --writers-stopped --apply
```

`--result absent` допустим только после подтверждения отсутствия документа. Он снимает неопределённость, увеличивает версию и требует нового согласования; сам ничего в iiko не отправляет. Команда также поддерживает `writeoff`. Нельзя разблокировать все неизвестные операции массовым UPDATE.

## Откат

После появления `queued` возврат к старому Django без обработки очереди небезопасен. Остановить новый worker и закрыть запись, сделать новый backup. Сначала завершить/сверить все queued/sending/unknown операции. Не включать прежних отправителей поверх неразобранной очереди и не восстанавливать старый снимок поверх новых документов. Предпочтительно исправить новый выпуск, сохраняя существующую базу.

## Тесты

`tests/test_native_documents.py` использует отдельную loopback PostgreSQL и искусственные данные; iiko и Telegram подменены. В CI база создаётся отдельно от аналитической тестовой схемы. Проверяются права, версии, идемпотентность, гонки web/bot, два обработчика, потеря ответа, восстановление процесса и операторская сверка. `tests/test_document_transport.py` проверяет контракты транспорта, часовой пояс, XML и маскирование секретов. Настоящие документы и уведомления тестами не отправляются.


## Telegram в «Мой профиль»

Авторизованный пользователь получает состояние через `GET /api/profile/telegram`, создаёт
ссылку через `POST /api/profile/telegram/link` и отключает Telegram через
`POST /api/profile/telegram/unlink`. Идентификатор берётся из текущей сессии.
`app/documents/telegram_link.py` предоставляет `status`, `issue`, `unlink` для HTTP-слоя.

До выпуска применить `migrations/documents/0002_telegram_link.sql` от migrator.
`CHAIKA_DOCUMENTS_BOT_USERNAME` необязателен: без него имя существующего бота
определяется через `getMe` и кешируется на час. Токен бота клиенту не выдаётся.
Ссылка содержит случайный одноразовый 256-битный секрет сроком на 10 минут;
БД хранит только SHA-256. Повторная выдача и отключение отзывают предыдущую ссылку.
Worker также заменяет секрет хешем до записи Telegram update в durable inbox.

`/start link_…` принимается только в личном чате. Привязка проверяет активность
портального и рабочего профилей, его текущую ревизию и уникальность Telegram ID
в одной транзакции. Уже подключённые аккаунты не перезаписываются; сначала нужна
явная отвязка. Обычный `/start` сохраняет прежний ответ с Telegram ID.

Если рабочего профиля нет, создаётся новый неадминистративный профиль без складских
прав. Совпадения email не используются. Склады, действия, аналитические права,
история документов и существующие события доступа не меняются. Ревизия связи
увеличивается при подключении/отключении, чтобы устаревшая форма администратора
не перезаписала изменение незаметно.

`tests/test_telegram_link.py` проверяет срок действия, повтор, гонки привязки,
отключённые профили, отвязку и сохранение прав в отдельной loopback PostgreSQL
`telegram_profile_tests`; бот подменён, внешние сообщения не отправляются.
Отдельная регрессия выполняет выдачу, привязку, отвязку и создание пустого профиля
под реальной ролью `chaika_iiko_app` (не superuser), проверяя права миграции.
