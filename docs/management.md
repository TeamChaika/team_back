# Управление dashboard

`/management` доступен только активным профилям с `is_portal_admin=true`.
Администраторы назначаются отдельно; форма не принимает изменение этой роли.

- «Сотрудники и доступы»: создание Auth-пользователя по почте и паролю (12–128 символов),
  имя, отключение входа, разрешённые пункты меню. Письма не отправляются.
- Заведения iiko выбираются для всех разрешённых разделов iiko. Новые учётные записи
  получают роль manager; доступ к разделу сотрудников iiko не выдаёт право изменять iiko.
- Для депозитов отдельно назначаются заведения, просмотр всех и право создания.
- «Заведения и терминалы»: создание/редактирование заведения, несколько терминалов,
  выбор терминала для выпуска новых QR. Отключённое заведение не принимает новые
  депозиты, существующие гостевые ссылки продолжают работать.
- API-ключи терминалов доступны только на запись. Пустое поле при редактировании
  сохраняет ключ. UUID терминала — справочное поле, платёж определяется API-ключом.

Все API проверяют раздел и активность профиля. Ассистент относится к «Закупочным ценам».
Прямой pay API и RLS также проверяют активность и доступ к депозитам. Названия заведений
переносятся в истории/правах одной транзакцией; старые названия остаются алиасами для
уже открытых гостевых ссылок. Выбранный терминал копируется в совместимые поля
`qr_enterprises`, используемые платёжным сервисом. Уже выпущенные QR не меняются.

Сохранение прав и конфигурации использует revision (конфликт 409 при устаревшем редакторе).
Аудит хранит только исполнителя, действие, идентификатор цели и время, без паролей/ключей.
Повтор создания сотрудника с тем же request_id и email восстанавливает незавершённое
создание профиля, но не сбрасывает права уже созданного пользователя.

## Развёртывание

1. Резервная копия таблиц профилей, прав и конфигурации депозитов.
2. Миграция `supabase/migrations/20260928143000_portal_administration.sql`.
3. Миграция сервиса pay `migrations/20260928_portal_administration.sql` после шага 2.
4. Серверная переменная `CHAIKA_WEB_AUTH_ADMIN_KEY` — Admin API key общего Supabase.
   Не передавать её в frontend. Все прежние переменные сохраняются.
5. Обновление pay auth.py, services/supabase_client.py, routers/deposits.py.
6. Обновление dashboard backend и frontend. Проверка точных коммитов, входа,
   создания пользователя, прав, отключения и конфигурации на опубликованном адресе.

Изменение терминала не проверяет его тариф/готовность у QR Manager и не создаёт платёж.
Контракт создания учётных записей: https://supabase.com/docs/reference/python/auth-admin-createuser
