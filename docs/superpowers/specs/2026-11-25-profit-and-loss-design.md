# Прибыли и убытки заведений

## Учёт

Бухгалтерия и менеджеры вводят операционные расходы по заведению. В каждой записи есть статья, сумма в рублях с копейками, дата расхода, способ оплаты (наличные или безналичные), дата оплаты и комментарий. У неоплаченной записи дата оплаты пуста. Одну запись можно дополнить датой оплаты после закрытия месяца. В отчёте владельца расход всегда относится к дате расхода. Например, ноябрьская аренда с оплатой 5 декабря уменьшает ноябрьский результат ровно один раз.

Владелец видит выручку после скидок, себестоимость продаж из iiko, валовую прибыль, введённые расходы по статьям и операционный результат по выбранным заведениям и периоду. При неполной загрузке продаж журнал доступен, итог за период ждёт полных данных. Ввод предназначен для расходов сверх себестоимости продаж. Оплата поставщику за уже учтённые продукты, перевод между своими счетами и изъятие из кассы сами по себе расхода не создают.

## Доступ

| Доступ | Записи | Прибыль |
| --- | --- | --- |
| Менеджер | Создаёт и видит свои записи в назначенных заведениях | Только владелец получает итоговый отчёт |
| Бухгалтерия | Создаёт записи и видит среди них записи всех авторов в доступных заведениях. Для бухгалтерии сети назначаются все заведения | Только владелец получает итоговый отчёт |
| Владелец | Видит журнал по заведениям в своём доступе | Полный отчёт |

Сотрудникам назначают доступ явно. Уровень бухгалтерии не выводится из названия должности или права администрирования. Права раздела, состав заведений, автора и данные для ответа проверяет сервер при каждом запросе. Учётные записи с доступом только к отдельным складам не получают финансовые данные целого заведения.

## Рабочий экран

Основной раздел Dashboard «Прибыли и убытки» содержит журнал расходов с фильтрами по заведению и периоду, кнопку «Добавить расход» и для владельца финансовую сводку. У менеджера список ограничен автором из сессии. В форме понятные статьи расходов, в том числе аренда, персонал, коммунальные услуги, ремонт, маркетинг и прочие. Повторная отправка формы после сбоя возвращает ту же запись. Для исправлений хранятся автор и история. Менеджер исправляет или отменяет свои записи до оплаты. После оплаты исправить или отменить запись могут бухгалтерия и владелец в рамках доступа. Отмена сохраняет историю, в итогах учитываются действующие суммы. Рабочие данные остаются в Dashboard.

## Выбор способа учёта

Пользователь выбрал учёт по дате расхода с отдельной датой оплаты. Кассовый вариант сместил бы расход в месяц оплаты. Для доступа выбран журнал собственных записей менеджера, общий журнал бухгалтерии и отчёт владельца. Разделение действует и для прямых запросов к API.

## Проверки

Для тестов используются вымышленные заведения, суммы и пользователи. Проверяются доступ автора, другого менеджера, бухгалтера и владельца, ограничения по заведению и складу, повтор сохранения, конкурентное исправление, оплата в следующем месяце, расходы при отсутствующих продажах и равенство расчёта выручке за вычетом себестоимости и действующих расходов. В рабочей системе проверяются опубликованный интерфейс и ответы на чтение без создания финансовых записей.
