# Прибыли и убытки заведений. План реализации

[Требования и доступ](../specs/2026-11-25-profit-and-loss-design.md)

- [ ] Добавить в закрытую схему `chaika` журнал расходов и историю изменений. Денежные суммы сохранять с двумя знаками. Повтор создания с тем же `request_id` и автором возвращает прежнюю запись. Проверять текущую ревизию, доступ к заведению и записи в транзакции. Разрешить менеджеру менять собственный расход до оплаты. После оплаты исправление и отмена доступны бухгалтерии и владельцу.
- [ ] Подключить к FastAPI отдельные права `profit-loss` (ввод) и `profit-loss-accounting` (расходы всех авторов в назначенных заведениях). Владелец получает отчёт по своей роли. Проверить ограничения по заведению, складам и автору. Использовать дневную выручку и себестоимость продаж Dashboard для сводки владельца. Суммировать активные расходы по дате расхода, в том числе неоплаченные.
- [ ] В рабочем React-интерфейсе добавить журнал, форму ввода, исправление, отмену и представление сводки для владельца. Даты расхода и оплаты показывать отдельно. Для неактивного либо архивного заведения оставить исторический просмотр. Для рабочих заведений ввод доступен независимо от оперативной синхронизации iiko.
- [ ] Проверить через API под вымышленными пользователями, что журнал защищён при чтении и записи, изменение оплаты не сдвигает расход между месяцами, пропущенные продажи не превращаются в ноль. Проверить клиентские состояния и сборку. После успешного CI применить миграцию, выпустить сервер и интерфейс, проверить рабочий маршрут без создания расходов в реальной бухгалтерии.
