# Архитектура

## Сервисы

`app.main` предоставляет технический API iiko и запуска синхронизаций. `app.portal` обслуживает пользовательский API, сессии Supabase Auth и собранный React-сайт. `app.progress` показывает состояние загрузок. Технические процессы запускаются в закрытой сети; пользовательский портал публикуется через HTTPS.

FastAPI получает данные из iiko и сохраняет их в PostgreSQL/Supabase. Браузер обращается к относительным адресам `/api` портала. Доступ к ресторанам проверяется сервером; ключи iiko, подключения PostgreSQL и провайдера ИИ хранятся только в локальной конфигурации backend.

## Синхронизация

- Запросы к одному серверу iiko выполняются последовательно. Токен повторно используется, выход освобождает лицензию.
- Исторические загрузчики сохраняют прогресс и поддерживают возобновление. Периоды делятся на ограниченные интервалы.
- Документы содержат исходные сведения и нормализованные строки для отчётов и расшифровок. Повторяющийся номер строки документа не считается уникальным идентификатором.
- Итоги OLAP сверяются между отчётами. Неполный период и расхождения должны оставаться видимыми пользователю.
- События заказов привязаны к RMS и ресторану; связи перемещений строятся по совместимым событиям. Отсутствие подтверждённой связи не заменяется предположением по номеру заказа.

Схема базы находится в `supabase/migrations`. Миграции применяются по порядку к подготовленному Supabase. Скрипт `tools/prepare_test_database.py` создаёт минимальную среду только для CI и не предназначен для настройки рабочего Supabase.

## Отчёты и помощник

Портал читает сохранённые данные. Расшифровки связывают показатели с документами, строками OLAP и событиями заказов. Расчёт изменения закупочной цены использует предыдущие поступления; оценка влияния на неделю использует техкарты и темп продаж. Это оценка будущих затрат, а не факт понесённых потерь.

Помощник по закупкам использует существующие функции расчёта и ограничения доступа портала. Настройки провайдера задаются по `.env.assistant.example`; пользовательские данные и ключ провайдера не входят в сборку frontend.

## Независимые сборки

`team_back` проверяет Python и миграции на временном PostgreSQL. `team_front` проверяет TypeScript и собирает `dist`. Оба workflow запускаются в ветке `chaikaiiko` и для pull request. Развёртывание на рабочем сервере и применение рабочих миграций требуют отдельной настройки CD.
